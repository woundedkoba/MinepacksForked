# Paper 26.3 API builds 34–40

Reviewed on 2026-09-24. These were the seven most recent 26.3 builds in [Paper's official build index](https://fill.papermc.io/v3/projects/paper/versions/26.3/builds) at review time. I compared the official `paper-api` source and binary JARs for each build, using build 33 as the baseline for build 34, and read the build index's Paper commit summaries. The exact Maven coordinate includes `-alpha` for all seven; this review does **not** treat that suffix as evidence of release maturity.

Across builds 34–40, `ItemStack`, `Inventory`, `ItemMeta`, `PluginDescriptionFile`, `Bukkit`, and `Server` sources are byte-for-byte identical. Builds 35–39 have identical Java source files; builds 35–39 also have identical class bytes, despite differing binary JAR hashes. The build 40 source change describes that empty suggestions are not sent to the client; the corresponding event class has no signature change. The only new public API surface across the seven builds is build 35's player post effects API.

The backpack risk sits below that public API: Minepacks embeds a version-specific NMS serializer. Inspection of the official **build 40 server implementation** found public `CraftItemStack.asBukkitCopy(ItemInstance)` and no `asCraftMirror`, so the embedded serializer has been rebuilt to use the former. The API comparisons cannot establish when this server method changed or prove runtime compatibility for builds 34–39. Build 40 starts and recognizes the single Minepacks plugin before the EULA gate; a complete enable and backpack save/restore across restart remain [release checks](Release%20Checklist.md). A newer Paper build needs another server implementation check even if its API JAR is unchanged.

## Reproduce the comparison

Download `paper-api-26.3.build.N-alpha-sources.jar` and `paper-api-26.3.build.N-alpha.jar` for N = 33–40 from the [official Paper Maven repository](https://repo.papermc.io/repository/maven-public/io/papermc/paper/paper-api/). Compare `.java` entries by SHA-256 and `.class` entries by SHA-256, ignoring archive metadata. Use the [build index](https://fill.papermc.io/v3/projects/paper/versions/26.3/builds) for publish times and associated Paper commits. This distinguishes changed archive packaging from changed API content.
